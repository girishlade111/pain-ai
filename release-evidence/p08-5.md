# PRD §8 Acceptance Evidence — Box 5: Permission Gate Enforcement

## Requirement
> File write + shell exec each gated (Allow Once works; Deny blocks; Workspace rule persists only in that folder; Global applies everywhere).

## Implementation & Verification

1. **Authoritative Gatekeeper (`src-tauri/src/gate.rs`)**:
   - Every file write (`ActionKind::FileWrite`), patch (`ActionKind::FilePatch`), and shell command (`ActionKind::ShellExec`) invokes `gate::check(&action)`.
   - Precedence: **deny > ask > allow**. Specificity never overrides order.
   - Every prompt card displays:
     - Risk badge: Low / Med / High
     - "What this does · Why · What could go wrong"
     - Reversible alternative where available

2. **Decision Modes Tested**:
   - **Allow Once**: Authorizes the single action execution. Does not write to rule store.
   - **Deny**: Strictly halts execution immediately with `PermissionDenied` error.
   - **Allow Always — Workspace**: Persists rule under `rule_store.workspace[current_dir]`. Re-executing in the same directory allows automatically; executing in a different directory prompts again.
   - **Allow Always — Global**: Persists rule under `rule_store.global`. Applies across all workspaces.

3. **Automated Gate Tests**:
   - `gate::gate_tests::tests::test_workspace_isolation`: PASS (workspace rule does not bleed into other directories)
   - `gate::gate_tests::tests::test_global_deny_overrides_workspace_allow`: PASS (global deny takes precedence)
   - `gate::gate_tests::tests::test_precedence_deny_overrides_allow`: PASS
   - `gate::gate_tests::tests::test_precedence_ask_overrides_allow`: PASS

## Verdict
**PASS** — Strict gate enforcement and scoping hierarchy verified.
